# Unicode Compilation Error Fix

## Problem
The bot was generating valid code that would sometimes fail with compilation errors in Java due to Unicode character encoding issues. The platform compiler uses US-ASCII encoding, which cannot handle special Unicode characters like smart quotes (", ", ', '), em dashes (—), en dashes (–), and ellipsis (…).

Example error from the platform:
```
Main.java:26: error: unmappable character (0xE2) for encoding US-ASCII
Main.java:26: error: unmappable character (0x80) for encoding US-ASCII
Main.java:26: error: unmappable character (0x91) for encoding US-ASCII
```

This occurred because LLMs (Large Language Models) sometimes generate these fancy Unicode punctuation marks instead of their ASCII equivalents, especially when copying code patterns.

## Root Cause
The `SolutionValidator.clean_and_validate()` method was extracting and validating code but not normalizing Unicode characters. While the bot's error handling flow was correct (detecting compilation errors and asking the AI to fix them), the AI couldn't reliably fix Unicode issues because:

1. The error message didn't always mention the specific Unicode characters
2. The AI would generate the same problematic characters again on retry

## Solution Implemented
Added Unicode normalization to `src/solver/validator.py` that:

1. **Replaces common problematic Unicode characters with ASCII equivalents:**
   - Left/right double quotes (" ") → straight quotes (")
   - Left/right single quotes (' ') → straight apostrophes (')
   - Em dash (—) → hyphen (-)
   - En dash (–) → hyphen (-)
   - Ellipsis (…) → three periods (...)
   - Bullet (•) → asterisk (*)

2. **Handles remaining non-ASCII characters** via Unicode NFKD normalization:
   - Decomposes accented characters to their base + combining marks
   - Strips non-ASCII components
   - Preserves the semantic meaning of the code

## Changes Made
**File: `src/solver/validator.py`**

1. Added import: `import unicodedata`
2. Added new static method `_normalize_unicode(text: str) -> str` that:
   - Maps Unicode punctuation to ASCII equivalents
   - Uses NFKD normalization for remaining non-ASCII characters
   - Handles edge cases gracefully
3. Updated `clean_and_validate()` method to call `_normalize_unicode()` before returning

## Impact
- **Immediate:** All future code generated by the solver will be automatically cleaned of problematic Unicode characters
- **Prevents:** Compilation errors due to encoding issues on the platform
- **Preserves:** Code logic and functionality (only character encoding is fixed)
- **Backward Compatible:** No changes to the bot's API or workflow

## Testing
The fix was validated with multiple test cases:
1. ✓ Smart quotes in code comments and strings
2. ✓ Em/en dashes in comments
3. ✓ Mixed Unicode punctuation
4. ✓ Full validation pipeline (markdown extraction + Unicode normalization)

All test cases pass successfully.

## Deployment
The fix is ready to deploy. Simply restart the bot with the updated `src/solver/validator.py` file, and all generated code will automatically be Unicode-normalized before submission.
